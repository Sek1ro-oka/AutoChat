# 人格层目录（V2 · Phase 2）

这个目录存放 AutoChat 的系统提示词。分两层，用途和生效时机不同：

| 层 | 文件 | 内容 | 生效时机 |
| --- | --- | --- | --- |
| 行为层 | `behavior.md` | 「作为群友的行为协议」：何时可以开口、怎么分句、什么时候闭嘴 | 保存后**需重启** |
| 人格层 | `characters/<名称>.md` | 角色卡：语气、口癖、偏好、禁区 | 保存后**即时生效**（下一条消息） |

## 优先级

```
SYSTEM_PROMPT（.env，若已设置 → 独占，忽略下面两层）
        ↓
behavior.md（若存在，前置拼接）
        ↓
当前启用的人格卡（若存在）
        ↓
src/persona.js 的内置默认人设
```

- 一切默认关闭：没有 `behavior.md`、没有启用的人格卡、`.env` 也没设 `SYSTEM_PROMPT` 时，合成结果就是内置默认人设，与升级前逐字节一致。
- 想完全自定义、不参与分层管理，就继续用 `.env` 的 `SYSTEM_PROMPT`。

## 管理方式

优先用**控制台**的「人格」页管理（列表 / 新建 / 编辑 / 另存为 / 删除 / 启用），改动会自动同步到这里。也可以直接编辑文件——人格卡按下一条消息即生效，行为层需要重启。

控制台保存人格卡时会做一次原子写入（临时文件 + 改名），因此断电或崩溃不会留下半截文件。SQLite 的 `personas` 表只保存**最近一次保存的内容作为镜像**，仅在某张卡的文件无法读取时兜底；文件始终是唯一事实来源，删掉文件就等于删掉这张卡。

## 约束

- 名称 1~40 字，可用中英文、数字、空格、点、短横线、间隔号；不能以点或空格开头/结尾，不能使用路径分隔符或 Windows 保留名（`con`、`nul`、`com1` 等）。
- 单张卡最多 64 KB，最多 50 张。
- 本目录中的 `README.md` 不会被当作人格卡（只扫描 `characters/`）。

## 文件

- `characters/默认角色.md` — 示例角色卡。**默认未启用**；在控制台点「启用」后它才会取代内置默认人设。
