# 拟人化群友（一代仿真）

对应 [V2 开发路线图](roadmap.md) 的 Phase 3。这里说明**机器人什么时候会自己开口**、**说出来长什么样**，以及它与预算、防刷屏、群管理之间的边界。

## 一句话口径

> **规则决定「何时说」，模型决定「说什么」。** 判断该不该开口不发模型、不花钱；只有真的开口才走一次模型调用，并和问答共用同一个每日账本。

所以「选择性沉默」是免费的——一个安静的群和一个热闹的群，花费不会因此拉开差距。

## 开关与默认值

**默认关闭。** `.env` 不写任何 `SOCIAL_*` 时，机器人行为与 Phase 2 完全一致：群里只 @ 才回。

```dotenv
SOCIAL_ENABLED=true            # 总开关（也可以在控制台「活跃度与静默」页打开）
SOCIAL_THRESHOLD=6             # 相关度阈值，低于它保持沉默
SOCIAL_COOLDOWN_SECONDS=45     # 两次主动发言的最小间隔
SOCIAL_DAILY_LIMIT=20          # 每个群每日主动发言条数上限
SOCIAL_CONTEXT_MESSAGES=12     # 送给模型的最近群消息条数
SOCIAL_MAX_CHUNKS=3            # 一条回复最多拆成几条消息
SOCIAL_MIN_DELAY_MS=900        # 发送前的反应时间下限
SOCIAL_MAX_DELAY_MS=2600       # 发送前的反应时间上限
SOCIAL_MESSAGE_TTL_HOURS=24    # 群消息流水保留时长
BOT_NAME=                      # 群里被叫的名字，含它就加分
BOT_NICKNAMES=                 # 逗号分隔的别名
```

阈值、冷却、每群日上限、以及每个群的静音开关**可以在控制台「活跃度与静默」页运行时修改**，立即生效并写入本机设置（`settings` 表），无需重启。`.env` 提供默认值。注意界面只提供前四项与冷场开关；**单群静音目前只有 API（`POST /api/social/config` 的 `{group,muted}`）能写**，页面上没有这个控件。

这四项（开关、阈值、冷却、日上限）还能在控制台「群管理」页**按群覆盖**：一个安静的群可以把阈值调高、日上限压低，热闹的群相反。未覆盖的项继承全局值。机制见 [按群特异化](groups.md)。

### 冷场冒泡与静默时段

群里长时间没人说话时，机器人可以主动冒泡（默认关闭）：`SOCIAL_IDLE_ENABLED`（总开关，默认 `false`）、`SOCIAL_IDLE_MINUTES`（多久没人说话算冷场，默认 `45`，范围 5~720）、`SOCIAL_IDLE_HOURS`（允许冒泡的时段，默认 `0-23` 即全天）。这三项在控制台「活跃度与静默」页里改是**保存后立即生效（无需重启）**，且都是**全局的**（不带 `group`，不能按群覆盖）。

时段格式是**单个** `H-H`：两端都用 0~23 的整点，且**起点不能大于终点**（`9-22`、`0-6`、`14-18` 合法）。它**不支持跨零点**，`22-6` 会被拒绝；也**只接受一个区间**，`0-6,22-23` 这种两段写法同样会被拒绝——想同时覆盖深夜和清晨，只能二选一，或者用 `0-23` 表示全天。

## 何时说：相关度打分

`src/social/attention.js`，纯规则、纯函数：

| 信号 | 权重 | 说明 |
| --- | --- | --- |
| 基准 | +1 | 每一条消息的起点 |
| 被 @ | 必回（不参与打分） | 但**由问答路径回复**，仿真不重复回答 |
| 回复了机器人的某条消息 | +4 | 已经在对话里 |
| 文本包含 `BOT_NAME` / `BOT_NICKNAMES` | +3 | |
| 是问句（问号结尾或含疑问词） | +2 | |
| @ 了别人 | +1 | 活的话题链 |
| 群活跃度（2 分钟内消息数） | +0.5/条，上限 +3 | 冷群不自言自语 |
| 深夜（00:00–05:59 北京时间） | −3 | |
| 与机器人刚说过的话重复 | −8 | 去重 |

**阈值不是常数**，会随风向微调（`requiredScore`）：

| 状态 | 调整 | 含义 |
| --- | --- | --- |
| 观望 `observing` | ±0 | 默认 |
| 试探 `probing` | −1 | 刚开过口，更容易接第二句 |
| 活跃 `active` | −2.5 | 有人接话，意愿更高 |
| 退场 `retreating` | +4 | 被冷落过，需要很强的理由才再开口 |

并且叠加「能量」（`energy`，0~1）：能量高于 0.5 会进一步降低门槛，且能量随空闲时间按 30 分钟半衰期衰减。

### 突发窗口：同一波消息只回一次

群里的「你」「在吗」「？」常常在一两秒内连着发，按条判分就会得到三次互相独立的结论。`src/social/priority.js` 给每条**已过门槛**的消息再算一个稳定的优先级，与分数分开——分数随风向和能量上下浮动，同一个分数在两天的含义并不一样，不能拿来排序：

| 优先级 | 来源 |
| --- | --- |
| 4 `addressed` | 被 @ 或被点名 |
| 3 `reply` | 回复了机器人的某条消息 |
| 2 `name` / `question` | 文本里有机器人的名字，或是问句 |
| 1 `others` / `base` | @ 了别人，或普通闲聊 |

窗口 `BURST_WINDOW_MS = 2000` 是常量而非配置项：每群记一条「上一次开口的时刻」，2 秒内到达的新消息只有在**严格更高**优先级时才顶替上一条，否则丢弃并记一条 `social_suppressed`（带两侧的优先级与原因）。不排队、不做 aging：排队会让最坏情况变成「窗口 + 队列」的叠加等待，aging 则是把一条能一句话说清的规则调成没人能解释的参数。

被 @ 的消息根本进不到这里（那是问答路径的活），但它会把窗口起点重置为此刻。窗口按时间戳惰性过期，不挂定时器：没有需要清理的句柄，测试也不必等真实的 2000 毫秒。

它不覆盖任何别的闸门——静音、开关、每日上限、预算、以及没到门槛的消息照旧被拒。唯一被越过的是冷却：冷却最短 5 秒而窗口只有 2 秒，若不越过，这套机制在线上永远没有机会生效。

## 状态机

每群一行 `sim_state`，四个状态：

```
        ┌──────────── spoke ─────────────┐
        ▼                                │
   观望 observing ──engaged──► 活跃 active │
        ▲                                │
        │                          ignored│
   cooled                                ▼
        └──────── 退场 retreating ◄── 试探 probing
                                          ▲
                                          └── spoke / engaged
```

- `spoke`：机器人刚发过言
- `engaged`：有人 @ 它、回复它、或提到了它的名字（且在上次发言后 3 分钟内）
- `ignored`：发过言之后 4 分钟没人理
- `cooled`：退场状态维持 15 分钟后回到观望

状态推进是**惰性的**：没有定时器，只有新消息到达时才根据「距上次发言多久」和「这条消息是否指向它」推进一步。

## 说什么：人味渲染

`src/social/renderer.js`：

1. **先去包装**：剥掉 markdown、代码块、行首的 `（动作）`/`【旁白】`；
2. **分句发送**：按 `。！？!?…` 切句，最多 `SOCIAL_MAX_CHUNKS` 条；超过上限才合并相邻句；单句过长（>60 字）在逗号处断开；
3. **发送间隔**：每条之间有 `SOCIAL_MIN_DELAY_MS`~`SOCIAL_MAX_DELAY_MS` 的随机停顿（第一条模拟"反应时间"，其余模拟"打字"）；
4. **不重复自己**：与最近 3 条机器人发言重复则整条丢弃——这是最容易被识破的一类"不像人"。

**口癖不在这里生成。** 语气、口癖、梗偏好属于人格层（Phase 2 的 `personas/characters/*.md`）。渲染层随机拼接"喵~"只会显得更假。

### 第二道沉默

送给模型的系统提示里明确要求：**不确定或无话可说时只输出两个字「不回」**。命中即静默，不说话也不发消息（费用已经产生，照常结算）。

## 上下文怎么组装

```
[群聊记录开始]
群友1：今天的题真难
你：二分就行
群友2：@机器人 你确定？
[群聊记录结束]
[引用 群友1：今天的题真难]
[当前这条消息] 群友2：那题真的能二分？
请只输出你要发送的内容，或只输出「不回」。
```

三条约束：

1. **QQ 号不进提示词**：群成员按出现顺序映射成「群友1、群友2…」，映射只在本进程内维护。
2. **引用是数据**：渲染成 `[引用 群友1：原文]`，用的是全角冒号；群消息里任何 `[` `]` 在进入提示词前都会被换成 `【` `】`，成员无法伪造我们的结构标记。
3. **不可信输入**：所有群文本在进入提示词前做扁平化与转义（控制字符、换行、长度上限），群友文本永远不被当成指令。

这套组装在 `src/social/prompt.js` 里，与「要不要说话」的判定逻辑（`engine.js`）分开：前者关心的是把一段不可信文本安全地渲染进提示词，后者关心规则、预算与时机，两者的失败模式不同。人格层与黑话表的拼接由 `withSlang()` 统一负责，问答路径与仿真路径共用同一份实现。

### 截断留痕

提示词只带最近 `contextMessages` 条群聊记录（默认 12），而环形缓冲记得更多。被裁掉的部分不再是无声无息：`dropped > 0` 时系统消息末尾会多一行

```
（更早的 8 条群聊记录已省略，本轮只带上最近 12 条）
```

这行只拼进 system 消息，**不进**给模型看的群聊记录本身——记录区是「谁说了什么」的渲染结果，标记混进去就成了某位群友的发言，模型完全可能照着学一遍再发到群里。同一时刻记一条 `social_context_truncated`（含群、`kept`、`dropped`、`contextMessages`），并且 `kept + dropped` 恒等于候选记录的总条数——当前这条消息单独占一行、不参与裁剪，也就不会被算成「省掉的」：没被带上的每一条都有着落。

冷场冒泡走同一个函数，标记与日志一致；历史本来就没满时不加标记、也不记事件。

### 群聊黑话表（Phase 4）

如果启用了黑话词库，**已确认**的词条会格式化成 `【群聊黑话表】` 追加在**人格提示词之后、行为附言之前**；私聊不带。这张表每次对话都重新读取，所以在控制台确认一个词之后，下一条群消息就会生效，无需重启。词条从哪来、谁批准、怎么转义，见 [群聊黑话词库](slang.md)。

## 与预算／防刷屏／群管理的边界

| 关系 | 规则 |
| --- | --- |
| 每日预算 | 主动发言前走 `store.reserve()` → `settle()`，与问答**共用同一个人民币账本**；`SOCIAL_DAILY_LIMIT` 是独立的条数上限，金额与条数双重约束 |
| 花费看板 | 采样会话键为 `social:group:<群号>`，在「计费看板」页单独可见 |
| 被 @ 的消息 | 由问答路径回复；仿真只把它记为"engagement"，**不会出现两条回复** |
| 图片消息 | 仿真不处理（由问答路径负责），直接跳过 |
| 防刷屏 | 机器人自己的发言不计入他人刷屏判定；仿真的主动发言受自己的冷却与日上限约束 |
| 群管理 | `/群关闭` 期间仿真同样不发言；控制台可对单个群静音 |
| 屏蔽词 | 入站命中 `BLOCK_TERMS` 不发言；出站命中则整条丢弃 |
| 模型不可用 | 保留预留（与问答同策略：超时请求可能已被上游计费），记 `social_model_failed` 事件 |

## 数据与隐私

| 表 | 内容 | 保留 |
| --- | --- | --- |
| `messages` | 群消息流水（群号、消息号、发言者、时间、文本） | `SOCIAL_MESSAGE_TTL_HOURS`，过期由维护任务清理 |
| `sim_state` | 每群状态、上次发言时间、能量 | 永久（每群一行） |

- **仿真关闭时不写 `messages`**：群聊正文不会因为开了这个功能而被动入库。
- **机器人自己的发言不入库**：它在 NapCat 侧的自消息回执并不可靠，重复记录会让机器人回复自己；自己的话只保存在进程内的环形缓冲里（每群 20 条），用于上下文与去重。重启后这部分记忆丢失，属于已知取舍。
- **控制台不展示聊天正文**：活跃度页只有状态、计数、阈值与"最近一次判定的原因"，永远没有消息文本。

## 控制台「活跃度与静默」页

- 四个指标：今日已发言的群数（含在册群数）、总开关、门禁（核心与群门禁）、今日记录（第几天）；
- 全局参数：相关度阈值、冷却秒数、每群日上限、插话开关、插话最短空闲分钟，以及 `SOCIAL_IDLE_HOURS`（这一项**从页面保存必定失败**，见下）；
- 每群表格：状态、能量、今日发言/上限、最近发言、最近一次判断（原因 · 分数 · 门槛）；
- 只读的配置文件项：上下文条数、最多切分数、最小/最大延迟、消息保留小时数。

有两个已知缺口：**单群静音没有控件**（只能调 API）；`SOCIAL_IDLE_HOURS` 被渲染成数字输入框并标成「插话最长空闲（小时）」，而后端要求 `H-H` 时段（如 `9-22`，起点 ≤ 终点、不支持跨零点），所以点这一项的「保存」会得到 `400 SOCIAL_PARAM_INVALID`——要改时段就改 `.env`。见 [控制台说明](console.md) 的「已知缺口」。

该页**不参与 3 秒轮询**（与「人格」页一致），避免定时重绘覆盖正在输入的数字；切页或点刷新即可更新。

## 日志事件

`social_skipped`（判定为不发言）、`social_suppressed`（突发窗口内被更高优先级顶替）、`social_context_truncated`（历史被裁掉，带 `kept` 与 `dropped`）、`social_priority_unknown`（打分给了一个未知原因，按最低档处理）、`social_spoke`、`social_declined`（模型回「不回」）、`social_repeat`、`social_blocked`、`social_empty`、`social_budget_blocked`、`social_model_failed`、`social_send_failed`、`social_context_failed`、`social_persona_failed`、`social_params_changed`、`social_failed`（参与者内部异常，会被 runtime 隔离）。

日志里只有事件名，没有消息正文。

## 怎么验证它真的在"像人"

1. `.env` 设 `SOCIAL_ENABLED=true`，重启；
2. 在群里正常聊天（不要 @ 它）——观察它**大部分时候不说话**；
3. 有人回它、或者它名字被叫到时，它才会接话，而且是 1~3 条短消息、中间有停顿；
4. 控制台「活跃度与静默」页能看到每群的判定原因：`below_threshold` 说明"沉默是判断出来的，不是坏了"；
5. 关掉开关，行为立刻回到"只 @ 才回"。

## 已知取舍

- 重启后机器人丢失自己的历史发言（不入库），可能重复一次刚说过的话；`isRepeat` 只能覆盖当前进程内记忆。
- **去重发生在生成之后**：`social_repeat` 是「模型已经答了、内容与刚说过的重复、于是不发出去」。这一次调用仍然计费——在不知道模型会说什么之前，没有更早的关口可以拦（不发言的关口都在模型调用之前，去重不是其中之一）。
- 高峰期与空闲期的判断不参与决策，只影响计价（见 [令牌与花费看板](cost.md)）。
- 主动发言的**话题选择**完全交给模型；仿真不做话题规划（那是 Phase 6 Agent 模式的范围）。
