# 空间说说

机器人自己发 QQ 空间说说：素材来自群聊，模型先判断「这事值不值得写」再给正文，正文还要过一道**绝对规则闸**（不带群号、不带链接、不带 @、不与上一条重复……），最后才发出去。

**默认关闭，开了以后默认还是干跑。** 两把锁都在 `.env` 里：`QZONE_ENABLED=false` 时进程连素材都不读；`QZONE_DRY_RUN=true` 时只生成草稿、一步之差停在发送之前。原因很直接——**发出去不是幂等的**：一条说说发出去就没有「撤销重试」，删掉也只是删掉自己这一条。

控制台入口见 [控制台说明](console.md) 的「空间说说」页签（第 10 个）与「系统设置」页；`QZONE_*` 与别的 `.env` 字段的读法约定见 [配置与服务管理](configuration.md)；每次生成的花费记进同一本账，见 [令牌与花费看板](cost.md)；正文离开这台机器的边界见 [安全与隐私基线](security.md)。

本文对过代码的日期：**2026-10-17**。动作名、闸门与失败语义以 `src/qzone.js`（`QZone` 的 `enabled`／`tick`／`publish`／`gate`／`tripFor`）、`src/qzone-material.js`（`prefilterReason`／`selectMaterial`／`MAX_BATCH`）与 `src/qzone-guard.js`（`guardPost`／`GUARD_REASONS`）为准；默认值与范围以 `src/config.js` 的 `qzone*` 字段为准。

## 它怎么工作

**不是定时发，是攒够素材才发**：

1. 只收已配置群（`GROUP_WHITELIST`，或单群模式下的那个群）的**群消息文本**；私聊不进来。说说自己往 `messages` 表记这些消息——即使 `SOCIAL_ENABLED=false`（仿真默认关闭、没人写这张表）也照记。
2. 只保留 `QZONE_MATERIAL_TTL_HOURS` 小时以内的素材，先过一遍[预筛](#素材预筛什么进不了模型)。
3. 过筛的素材按时间升序排，**攒够 `QZONE_BATCH_MIN` 条才触发一次**，一次最多 60 条（`MAX_BATCH`）。
4. 触发后先过三道频率闸，任何一道不过就**不调模型、不花钱**：今日已满 `QZONE_MAX_PER_DAY`（事件 `qzone_daily_cap`）、距上一条不足 `QZONE_MIN_GAP_HOURS`（`qzone_min_gap`）、当前小时不在 `QZONE_HOURS` 内（`qzone_window`）。
5. 一次模型调用同时做两件事：判断值不值得写，并直接给出正文。约定形状是 `{"worthy":true,"text":"…"}` 或 `{"worthy":false}`；模型说「不写」也算处理过——游标前进，这批素材不会再被看第二遍。
6. 正文过[出站闸](#出站闸什么发不出去)后，按 `QZONE_UGC_RIGHT` 调 `send_qzone_msg` 发出去。

维护定时器每 **30 秒**跑一拍，同一时间只允许一次评估在跑。**总开关关闭、或机器人被 `/停止` 全局停用时，这一拍直接返回**：一个被停用的机器人不该还在外面发说说。

日上限与最小间隔都只按**当天**已有的 `drafted`（干跑草稿）与 `sent`（已发布）行来算：草稿也算，因为它是一次花了钱、也占着当天额度的生成；被拦截与失败的不算。账期按北京时间零点切。

## 素材预筛：什么进不了模型

`src/qzone-material.js` 的 `prefilterReason` 逐条返回原因，命中即丢，模型永远看不到：

| 原因 | 丢弃条件 |
| --- | --- |
| `own` | 机器人自己发的 |
| `empty` | 去掉空白后没有正文（纯图、纯表情包消息） |
| `command` | 以 `/` 开头的命令 |
| `length` | 少于 4 字或多于 200 字 |
| `emoji` | 没有任何「有意义」的字符（只有表情与标点） |
| `link` | 含 `http(s)://` 或 `www.` 链接 |
| `number` | 含 5～12 位连续数字（多半是 QQ 号、群号、手机号） |
| `mention` | 含 `@` |
| `markup` | 含 `【`（多半是 CQ 码或别的机器人的指令） |
| `term` | 命中 `BLOCK_TERMS` |

预筛只是第一层：它决定什么能进模型，**不决定什么能发出去**。

## 出站闸：什么发不出去

`src/qzone-guard.js` 的 `guardPost` 对模型给的正文做绝对规则检查，命中任何一条就**放弃这一条**，写一行 `blocked` 记录原因，这批素材标记为已处理、不重试。`GUARD_REASONS` 一共 7 个：

| 原因 | 规则 |
| --- | --- |
| `length` | 长度不在 8～200 字（按字符数，不是字节） |
| `groupid` | 正文里出现任何白名单群号 |
| `number` | 含 5～12 位连续数字 |
| `link` | 含 `http(s)://` 或 `www.` 链接 |
| `markup` | 含 `@`、`【`、`】` 或 `[CQ:` |
| `term` | 命中 `BLOCK_TERMS` |
| `repeat` | 与最近 3 条草稿／已发布正文的相似度 > 0.8 |

提示词里要求的是 10～60 字，闸门放宽到 8～200 字：模型偶尔会写长一点，那不该被当成错误，但也不许写成一篇小作文。日志里只记原因与长度（`qzone_blocked` 带 `reason`、`len`），不记正文。

## 九个开关

| 键 | 默认 | 范围 | 控制台能改 | 含义 |
| --- | --- | --- | --- | --- |
| `QZONE_ENABLED` | `false` | `true`／`false` | 是 | 总开关。关闭时既不读素材也不调模型 |
| `QZONE_DRY_RUN` | `true` | `true`／`false` | 是 | 干跑。开着时生成草稿但不发送 |
| `QZONE_UGC_RIGHT` | `4` | `1`／`4`／`16`／`64`／`128` | 是 | 可见范围，见下节 |
| `QZONE_MAX_PER_DAY` | `1` | 1～10 | 是 | 每天最多几条（草稿也算） |
| `QZONE_MIN_GAP_HOURS` | `6` | 1～72 | 是 | 两条之间的最小间隔（小时） |
| `QZONE_HOURS` | `9-23` | `H-H`，0～23，起点 ≤ 终点 | 是 | 允许发布的小时窗口 |
| `QZONE_BATCH_MIN` | `8` | 3～60 | 是 | 攒够多少条素材才触发一次 |
| `QZONE_MATERIAL_TTL_HOURS` | `6` | 1～24 | 是 | 素材的有效期（小时） |
| `QZONE_MODEL_OUTPUT_TOKENS` | `300` | 64～1024 | **否** | 生成正文的输出上限 |

前 8 项在控制台里改是**保存后立即生效**，写进 `settings` 表的 `cfg:qzone_*` 键，空值表示回退 `.env` 默认。最后一项**故意不在运行时字段表里**：它同时决定一次生成要预留多少预算，中途改会让已经记下的估算与实际对不上，所以只能改 `.env` 后重启。

两处校验：布尔项必须是 `true`／`false`；`QZONE_HOURS` 必须是 `H-H`（如 `9-23`），**不支持跨零点**——`22-6` 会被配置校验拒绝，要覆盖夜间就写 `0-23`。`QZONE_UGC_RIGHT` 先按 1～128 的整数放行，再由白名单收紧到那五个值。

## 可见范围

| 值 | 含义 | 说明 |
| --- | --- | --- |
| `1` | 公开 | 所有人可见 |
| `4` | 好友 | 只有好友可见（默认） |
| `16` | 仅自己 | 只有自己能看，适合先在真实空间里看效果 |
| `64` | 密码 | 需要密码才能看 |
| `128` | 指定人 | 只给指定的人看 |

本程序只发两个参数：`content`（正文）与 `ugc_right`（这个数字），**不带密码，也不带指定人名单**。所以 `64`／`128` 在空间侧很可能按「空密码／空名单」处理——没实测过之前，用 `1`／`4`／`16`。

## 记录与状态

每次评估结果落在 `qzone_posts` 表（`id`、`at`、`text`、`ugc_right`、`status`、`reason`、`tid`），**只保留最近 50 条**；游标存在 `settings` 的 `qzone:cursor`，值是最高一条已评估素材的时间。五种状态：

| 状态 | 含义 | 界面 |
| --- | --- | --- |
| `sent` | 已发布，有 `tid` | 「已发布」，可删 |
| `drafted` | 干跑草稿，没发出去 | 「草稿（干跑）」 |
| `blocked` | 被出站闸拦下 | 「已拦截」，只显示原因 |
| `failed` | 发送失败 | 「失败」，只显示原因 |
| `deleted` | 已在控制台删掉 | 「已删除」 |

正文只进这张表与「空间说说」页，**不进日志**：`qzone_sent` 与 `qzone_drafted` 只带长度（`qzone_sent` 另有 `ugc_right`），`qzone_blocked` 只带原因与长度。`blocked` 与 `failed` 的行在界面上只显示原因、不显示正文。

## 发出去之后

- 发布成功后会**私聊一条通知给管理员**（`ADMIN_QQ`），内容包括时间与正文。通知失败只记 `qzone_notify_failed`，不影响已经发出去的说说。也就是说正文会进你的 QQ 私聊记录——介意的话在 QQ 里把那条私聊也删掉。
- 删除只在控制台「空间说说」页：先调 `delete_qzone_msg`，**成功之后**才把行标成 `deleted`。干跑、拦截、失败的行没有 `tid`，协议端没有可删的对象，界面也不给按钮。
- **只能收回自己这一条。** 被截图、被转发、被别人引用之后，那些副本已经离开这台机器，删说说收不回来。
- 删除失败按协议侧分类：`QZONE_DELETE_UNAVAILABLE` 503、`QZONE_DELETE_TIMEOUT` 504、`QZONE_DELETE_REJECTED`／`QZONE_DELETE_FAILED` 502；这些码在页面上都有对应文案。

## 失败语义

| 触发 | 结局 | 事件 |
| --- | --- | --- |
| `retcode` 为 `-10000`（限流） | 写 `qzone:blocked:<当天>` 标记，**当天不再尝试**；后续每拍连素材都不读 | `qzone_rate_limited` |
| `-3`／`-100`／`-3000`／`-10001`／`-10006`（认证类） | **本进程内永久关闭**，重启才可能恢复 | `qzone_unavailable`（带 `code`） |
| 传输层报 `ONEBOT_ACTION_FAILED`（分不出原因） | 按最保守的读法当认证失败处理，本进程不再尝试 | `qzone_unavailable` |
| 网络错误、超时、其它发送失败 | 记为 `failed`／`send_failed`，**不重试** | `qzone_send_failed` |
| 发送成功但响应里没有 `tid` | 记为 `failed`／`no_tid`，**绝不重发**（说说可能已经发出去了，重发就是两条） | `qzone_send_failed` |
| 模型返回不可解析／`worthy:false`／正文为空 | 记为 `qzone_skipped`（原因分别是 `unparsed`／`unworthy`／`empty`），游标前进 | `qzone_skipped` |
| 预算不够预留 | 这一轮不写，素材留到下次 | `qzone_budget_short` |

**没有任何自动重试。** 出错就放过这批素材，不存在补发通道；限流标记按天存，重启不会清掉它，第二天自然失效。

## 灰度：三步走

1. **只看草稿**：`QZONE_ENABLED=true`，`QZONE_DRY_RUN` 保持默认 `true`，重启。等第一批素材攒够（`QZONE_BATCH_MIN` 条），到「空间说说」页看草稿：正文、可见范围、拦截原因都在那儿。这一步**什么都不会发出去**。
2. **调到位**：改人格卡、调 `QZONE_BATCH_MIN`／`QZONE_HOURS`／`QZONE_MAX_PER_DAY`，让草稿出现在你想要的时间与语气上。记住草稿也占额度，一天最多 `QZONE_MAX_PER_DAY` 条。
3. **关干跑**：把 `QZONE_DRY_RUN` 改成 `false`（页面上保存即生效，不用重启）。下一条过闸的就会真的发出去；页头横幅会从「还在干跑」变成「正在真实发布」。

## 回滚

- **立刻停手**：把 `QZONE_ENABLED` 关掉（页面上保存即生效）。总开关关闭后下一拍直接返回，既不发也不再生成。
- **连进程内状态一起清**：关掉开关再 `restart.cmd`。认证失败留下的「本进程已停用」只在内存里，重启就没了；限流标记是按天存的，重启不会清，第二天自然失效。
- **已经发出去的**：只能到「空间说说」页逐条删，而且只收得回自己这一条。

## 不做的事

- **不按时间表发**：没有「每天固定几点发一条」的配置，只有「素材攒够了、而且过了频率闸」。
- **不限制素材群**：白名单群里所有能过预筛的消息都可能成为素材，没有「哪些群不参与」的开关。
- **不做兜底**：模型失败、预算不足、被拦截都只是跳过这一轮，不会退化成「随便发一句」。
- **没有第二次机会**：干跑草稿不会在你关掉干跑之后被补发——它只是记录。
