# AutoChat V2 开发路线图：Web 控制台与拟人化群友

版本：v1.0（规划稿）
日期：2026-10-04
状态：待确认；确认后按本文档分阶段推进，每阶段先落测试再合并。
参照项目：[qq-bridge](https://github.com/Derpyu520/qq-bridge)（架构与经验），调研日期 2026-10-04。

---

## 1. 背景与目标

### 1.1 现状

AutoChat 当前是一个**严格被动的问答机器人**：群内必须 @ 才回复，私聊按白名单回复；一次请求=一次模型调用=一条回复。工程质量已不错——持久化预算账本、事件去重、有界串行队列、防刷屏、群管理、图片识别、联网搜索、多模型配置、97 项自动化测试。

但它缺少两件东西：

1. **没有任何可视化界面**：所有状态只能靠 `/状态` 私聊命令和翻 `logs/*.jsonl`。
2. **没有"群友感"**：不会主动接话、不会引用、不会分句、不会选择性沉默。它是一个"叫它才答"的工具，不是"坐在群里的人"。

### 1.2 目标

- **目标 A（控制台）**：一个本机 Web 控制台，能观测运行状态、会话、预算与花费，并能管理人格与仿真参数。
- **目标 B（拟人化群友）**：在群聊中像真人一样**选择性参与**——判断"该不该说"，而不是"被 @ 才说"；说出来要像人（短句、口癖、偶尔沉默）。

### 1.3 参照与不照搬

qq-bridge 已经把这两件事做到了很成熟的形态（10 页控制台、一代/二代仿真、黑话词库、峰谷分时花费看板）。它的技术栈是 **DSH（DeepSeek Harness）+ MCP 工具集 + SnowLuma SDK**，`src/bridge.js` 单文件约 10400 行。

**本路线图只借鉴它的架构思想与踩过的坑，不引入它的技术栈。** AutoChat 的既有约束继续成立：

- 运行环境只有 Node.js ≥ 24，**唯一第三方依赖 `ws`**，不做构建步骤；
- 单进程、单实例、本机回环、Windows 优先；
- 预算安全第一：任何新增的模型调用都必须走现有"预留 → 结算"账本；
- 向后兼容：现有 `.env` 不改动也能继续运行。

## 2. 对照分析：AutoChat 现状 vs qq-bridge

| 维度 | AutoChat 现状 | qq-bridge 做法 | V2 采纳结论 |
| --- | --- | --- | --- |
| 运行时模型 | 单次问答（一问一答） | Agent 运行时，模型可多步、可调工具 | **部分采纳**：先做"规则管何时、模型管说什么"的一代仿真；Agent 化留作 Phase 6 可选 |
| 触发 | 群内必须 @；私聊白名单 | `chat`（白名单）/ `closed-agent` / `reserved`（一代仿真）/ `reserved2`（二代仿真） | **采纳**：新增"仿真模式"作为群聊的第 4 种触发方式，@ 触发保留 |
| 提示词 | 单层：`src/persona.js` + `.env SYSTEM_PROMPT` | **两层**：仿真提示词（行为协议，预设）+ 人格提示词（`roles/*.md`，热更新） | **采纳**：拆成"行为层（内置，需重启）+ 人格层（`personas/characters/*.md`，即改即生效）" |
| 控制台 | 无 | 本机 `127.0.0.1:3100`，10 页，深浅主题，全局搜索，token 鉴权 | **采纳**：自建 `node:http` 控制台，先 v1 只读，再逐步加页面 |
| 计费 | 单一定价（按高峰价保守预留）；今日汇总 | 峰谷分时（高峰×2）、逐场景/逐轮下钻、24h/3d/7d/30d 走势图、缓存命中率 | **采纳**：Phase 5 做分时看板；预留仍用高峰价（保守不变） |
| 群上下文 | 只保存"群+用户"会话，不存群消息流水 | 群消息流水 + 会话投影 | **采纳**：新增 `messages` 表（TTL 保留，仅存仿真所需最小字段） |
| 引用/回复 | 不解析 | 解析成`[引用 某人：原文]`注入，让 AI 知道在跟谁说话 | **采纳**：Phase 3 |
| 黑话/梗 | 无 | 学习器+联网确认+人工确认+注入`【群聊黑话表】` | **采纳**：Phase 4 |
| 表情/贴纸 | 文本 + QQ 表情转名 | 表情包库 + 收藏表情 | **暂缓**：收益低于成本，留作后置 |
| 语音 | 无 | 独立 voice-tool + 语音库 | **不做**：与本项目目标无关 |
| 安全 | 回环+token+白名单 | `SECURITY_BASELINE.md` 威胁模型 + ACL 收紧 + 工具白名单 | **采纳**：Phase 1 起补安全基线文档与"改动检查单" |
| 文档组织 | `docs/` 6 篇，README 直接引用 | 根目录只留 3 篇，`docs/` 按用途分子目录，带"是否仍有效"索引 | **部分采纳**：加文档索引，但不重排现有目录 |

## 3. 设计原则（不变量）

1. **零新增运行时依赖**：控制台用 `node:http`，前端单文件 HTML（无打包、无 CDN 强依赖）。
2. **本机回环**：控制台只绑定 `127.0.0.1`，默认开 token 鉴权（首启自动生成）。
3. **预算不可绕过**：拟人化的每一次主动发言都和问答共用同一个每日账本，走"预留→结算"。
4. **可验证**：每个 Phase 都先写测试再写实现；网络联调用假 OneBot/假模型服务器，不发真实 QQ 消息、不消耗真实额度。
5. **向后兼容**：新功能默认关闭；旧 `.env` 不改也能启动，行为与今天一致。
6. **小文件**：单文件不超过约 400 行；超过就按职责拆模块（吸取 qq-bridge 单文件 10400 行的教训）。
7. **不可信输入**：群消息一律视为不可信文本；注入提示词前做转义，不让群友文本变成指令。

## 4. 目标架构

### 4.1 分层

```
                         ┌─────────────────────────────┐
  NapCat (OneBot v11) ──► │  onebot.js  (WS 客户端)      │
                         └──────────────┬──────────────┘
                                        │ 事件
                         ┌──────────────▼──────────────┐
                         │  runtime.js  事件分发/参与者总线 │  ← 新增
                         └───┬────────┬────────┬───────┘
                             │        │        │
              ┌──────────────▼──┐ ┌───▼─────┐ ┌▼──────────────┐
              │ bot.js          │ │ social/ │ │ console/      │
              │ 问答/命令/管理   │ │ 仿真引擎 │ │ Web 控制台     │
              └────────┬────────┘ └────┬────┘ └───────┬───────┘
                       │               │              │ 读/写
                       └───────┬───────┴──────────────┘
                               ▼
                    ┌──────────────────────┐
                    │ store.js  (SQLite)   │
                    │ 会话/账本/事件/群/    │
                    │ 消息流水/人格/黑话/   │
                    │ 仿真状态/逐轮采样     │
                    └──────────────────────┘
```

关键变化：`main.js` 不再直接把 OneBot 事件塞给 `Bot`，而是交给一个 **runtime 分发层**。这样群消息可以同时被"问答处理器""仿真引擎""消息流水记录器"消费，且互不干扰（各自独立的有界队列与异常隔离）。

### 4.2 新增目录

```
src/
  runtime.js            # 事件分发 + 参与者注册 + 生命周期
  console/
    server.js           # node:http 服务：静态资源 + JSON API + token 鉴权
    api.js              # 各 API 端点的数据组装（纯函数，便于测试）
    public/index.html   # 单文件前端（深浅主题 + 页面路由）
  social/
    engine.js           # 状态机：何时说（观望/活跃/试探/退场）
    attention.js        # 相关度打分（是否被点名/引用/在话题链上/时间/活跃度）
    renderer.js         # 人味渲染：分句、口癖、错别字、选择性沉默
    slang.js            # 黑话库：提取/确认/注入（Phase 4）
    quote.js            # 引用/回复解析（Phase 3）
  ledger.js             # 峰谷分时计价 + 逐轮采样（Phase 5，从 store 拆出）
personas/
  behavior.md           # 行为层提示词（仿真协议；内置默认，可覆盖）
  characters/
    默认角色.md          # 人格层，控制台可编辑，即改即生效
```

### 4.3 数据模型（新增表）

| 表 | 用途 | 保留策略 |
| --- | --- | --- |
| `messages(group_id, message_id, user_id, at, text, kind)` | 群消息流水，供仿真相关度、黑话提取、统计 | 默认保留 24h，定期裁剪 |
| `persona(name, content, updated)` | 人格卡（与文件双写：文件为准，DB 做索引/回滚） | 永久 |
| `slang(...)` | 黑话词条（candidate/confirmed/rejected） | 上限 2000 条，超限按优先级裁剪 |
| `sim_state(group_id, state, last_spoke_at, energy, updated)` | 每群仿真状态机 | 永久（小） |
| `token_samples(turn_key, session, turn, seq, at, miss, hit, out, bucket)` | 逐轮 token 采样 | 上限 20000 行后压缩重写 |
| `charges` 扩展 `bucket` 列 | 记账时标注 peak/off | 随现有清理 |

> 逐消息正文只用于仿真与黑话，**不进日志、不发给模型多于必需的部分**；控制台展示会话内容需显式点击。

## 5. 分阶段计划

> 每一阶段都是"可独立验收、可独立回滚"的一步。**每个 Phase 结束必须：新增测试全过 + 现有 97 项测试不回归 + 更新 `docs/development.md` 进度表。**

### Phase 0 — 地基（结构重构 + 数据层扩展）

**目标**：把"能加东西"的结构铺好，不改变任何对外行为。

- 新增 `src/runtime.js`：参与者注册与事件分发；异常隔离（一个参与者抛错不影响其他）；每个参与者独立有界队列。
- `store.js` 建表：`messages` / `persona` / `slang` / `sim_state` / `token_samples`；`charges` 加 `bucket` 列（默认 `peak`，兼容旧数据）。
- `config.js` 扩展：新增开关（`SOCIAL_ENABLED`、`CONSOLE_ENABLED` 等）全部**默认关闭/false**。
- 抽 `budget` 相关逻辑到注释清晰的独立函数，为 Phase 5 分时计价留接口。

**交付物**：重构后的 `runtime.js`、扩展的 `store.js`、迁移脚本（幂等建表）。
**测试**：事件分发隔离、建表幂等、旧库升级不丢数据。
**验收**：`npm test` 全绿；旧 `.env` 启动行为与今天完全一致。

### Phase 1 — Web 控制台 v1（只读观测）

**目标**：打开浏览器就能看到机器人在干什么。

- `console/server.js`：`node:http` 服务，**只绑定 `127.0.0.1`**；首启生成随机 token，写 `runtime/console-token.txt` 并打印到日志；所有 `/api/*` 校验 token（header 或 cookie），静态页放行。
- API（只读）：`/api/summary`（连接态、开关、今日预算、队列深度）、`/api/sessions`（会话列表：条数、最后活跃）、`/api/charges`（按天/按会话汇总）、`/api/logs?limit=`（最近事件，已脱敏）、`/api/config`（生效配置，密钥打码）。
- 前端 `public/index.html`：单文件，**深浅主题跟随系统 + 手动切换**，左侧按页导航，3 秒轮询。
- `docs/console.md`：访问方式、token 位置、API 说明、安全边界。

**交付物**：可访问的控制台（默认 `http://127.0.0.1:3200`）。
**测试**：API 鉴权（无 token=401、错 token=401）、密钥不泄漏、只绑回环、页面可渲染（离线断言关键节点）。
**验收**：本机能打开控制台看到真实状态；局域网其他设备无法访问。

### Phase 2 — 人格与两层提示词

**目标**：人设变成可管理的文件，而不是埋在 `.env` 里的一长串。

- 两层拆分：
  - **行为层** `personas/behavior.md`：定义"作为群友的行为协议"（何时可以说话、怎么分句、什么时候闭嘴）。保存后需重启。
  - **人格层** `personas/characters/*.md`：角色卡（语气、口癖、梗库偏好）。控制台保存**即改即生效**。
- 加载器：内存缓存 + 文件监听；`SYSTEM_PROMPT` 仍作为最高优先级覆盖（向后兼容）。
- 控制台"人格"页：列表 / 新建 / 编辑 / 另存为 / 删除 / 启用。

**交付物**：`personas/` 目录、加载器、控制台人格页。
**测试**：加载回退顺序（`SYSTEM_PROMPT` > 人格卡 > 内置默认）、文件损坏时的容错、路径穿越防护。
**验收**：控制台改人格卡 → 下一条群消息立即生效，无需重启。

### Phase 3 — 拟人化群友（一代仿真）★ 目标 B 核心

**目标**：AI 在群里**自己判断该不该说话**，说出来像人。

设计要点（借鉴 qq-bridge 的 `SOCIAL_MODE_PLAN`：**规则管"何时说"，模型管"说什么"**）：

1. **相关度打分 `attention.js`**（规则，不发模型、不花钱）：

   | 信号 | 方向 |
   | --- | --- |
   | 被 @ / 被引用机器人 | 强正，直接进入"必回" |
   | 消息含机器人名/口癖 | 正 |
   | 处于机器人参与过的话题链（近 N 条） | 正 |
   | 是问句、直接提问、带 @ 别人 | 中正 |
   | 群整体活跃度高 | 正（冷群不自言自语） |
   | 深夜时段 | 负 |
   | 与"刚说过的梗"重复 | 强负（去重） |
   | 冷却中 / 当日主动发言额度用尽 | 直接否决 |

2. **状态机 `engine.js`**（每群一个实例）：
   `观望(observing)` 默认态 → 分数越阈且限流允许 → `试探(probing)` 生成一条候选 → 若被回应 → `活跃(active)`（提高意愿）→ 话题冷却/被冷落 → `退场(retreating)` 并设长冷却 → 回 `观望`。

3. **人味渲染 `renderer.js`**（借鉴"真人语感策略"）：
   - **分句发送**：按标点切成 1~3 条短消息，间隔 0.8~2.5s 随机延迟发送；
   - **口癖与变体**：随机选口癖收尾，避免每次同一句；允许轻微错别字/谐音；
   - **选择性沉默**：分数不够就**真的不发**——这是"像人"最重要的一条；
   - **长度纪律**：群里默认 1~3 短句，不写长段落、不写舞台动作。

4. **引用解析 `quote.js`**：把 QQ 引用解析成 `[引用 某人：原文]` 注入上下文，让 AI 知道这句话对谁说，不把"群友互相引用"误当成对自己说。

5. **成本与安全协同**：
   - 每次主动发言前走现有预留/结算；
   - 新增**主动发言日上限**（独立于金额，控制"话痨"）；
   - 与 `anti-spam` 协同：机器人自己发言不计入对他人的刷屏判定，但机器人的主动发言要受自己的冷却；
   - 与群管理协同：被 `/群关闭` 的群不参与。

6. **控制台"仿真"页**：总开关、每群状态、相关度阈值、冷却、日上限、当前能量值，实时可调。

**交付物**：`social/*` 四个模块 + 控制台仿真页 + `docs/simulation.md`。
**测试**：相关度打分边界、状态迁移、去重、冷却、日上限、预算不足时不发言、被 @ 时必然回、分句规则、引用解析。
**验收**：群里不发 @ 也会在合适时机接话；连发同一梗会被去重；关掉开关立即变回今天的"只 @ 才回"。

### Phase 4 — 黑话词库

**目标**：AI 逐渐听懂群里的话。

- 提取：周期性把 `messages` 里最近的群消息交给模型，识别"疑似黑话候选"（拼音缩写、网络流行语、群内梗）；
- 确认：候选可用联网搜索考究含义（复用现有搜索能力）；**必须在控制台人工点"确认"后才注入**，避免学歪；
- 注入：把已确认词条格式化成 `【群聊黑话表】`（按出现次数排序，最多 8~30 条），附加到群聊系统提示；
- 健壮性（直接照抄 qq-bridge 踩过的坑）：
  - 词库**有容量上限**（2000），超限按"已确认 > 出现次数 > 最近更新"裁剪；
  - **文件不存在 ≠ 读失败**：读失败时把原文另存为 `.corrupt-<时间戳>` 并报错，绝不返回空数组覆盖；
  - 提取群消息前**转义**，防止 prompt injection；
  - 从模型输出里抠 JSON 用**括号配平扫描**，不用贪婪正则（否则一句"根据[1]…"就能让解析失败且静默丢结果）。

**交付物**：`social/slang.js` + 控制台黑话页 + `docs/slang.md`。
**测试**：上限裁剪、损坏容错、转义、JSON 抽取（含"前缀解释+数组"场景）、状态流转。
**验收**：控制台能看到候选并确认；确认后的词出现在后续群聊上下文里。

### Phase 5 — 令牌与花费看板

**目标**：看清钱花在哪、什么时候贵。

- `ledger.js`：逐轮 token 采样（输入未命中/命中/输出分开记），**峰谷分时计价**（DeepSeek 高峰=空闲×2，高峰为北京时间工作日 9:00–12:00、14:00–18:00，排除法定节假日）；
- 三条实现要点（照抄 qq-bridge 的经验）：
  1. **不自己累加总量**，以服务端 totals 为权威值 + 基线之后的增量；
  2. **幂等折叠**：按 `(session, turn, seq)` 建键，只有 seq 严格更新才覆盖，重放不翻倍；
  3. **先落盘再进内存**：断线时清 per-turn 状态，采样一到就 append。
- 控制台页：4 个顶部指标（总花费/累计 token/缓存命中率/平均每轮）+ 走势图（24h/3d/7d/30d，柱子按峰谷着色）+ 按会话表 + 逐轮下钻 + 流水。
- **预算口径不变**：预留仍按高峰价保守估算；看板展示的"真实折算"是**报表**，不是预算放松。

**交付物**：`ledger.js` + 控制台花费页 + `docs/cost.md`。
**测试**：峰谷判定（含节假日）、四桶不重叠、幂等折叠、基线合并、半行容错、分桶边界不抖。
**验收**：看板金额与手工核算一致；切换范围桶数受上限约束。

### Phase 6（可选，后置）— Agent 模式

**目标**：把"一切皆工具"做进 AutoChat（对应 qq-bridge 二代仿真）。

- 让模型通过工具自主决定"看消息 / 发言 / 等待 / 潜水"，而不是每条都在状态机里被动触发；
- 必须配套**工具白名单**（只暴露安全的 QQ 只读/发送工具）与**工具调用预算**。

**前置条件**：Phase 0~5 全部稳定 + 明确需要"更自主"的场景。**不达标不做。**

## 6. 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 控制台技术 | `node:http` 自建 + 单文件前端 | 保持"唯一依赖 ws"；无构建步骤；审计简单 |
| 数据存储 | 继续用 `node:sqlite` | 已成熟、零依赖、事务可用；黑话/人格等小数据也可落库 |
| 拟人化范式 | 规则管"何时"、模型管"说什么" | 相关度判断不需要花钱调模型；成本可控且可解释 |
| 主动发言的预算 | 与问答**共用同一账本** + 独立日上限 | 防止"话痨"烧钱；金额与条数双重约束 |
| 群消息留存 | 默认 24h TTL，仅存最小字段 | 仿真与黑话够用；降低隐私面 |
| 人格热更新 | 人格层即改即生效；行为层需重启 | 行为协议改动影响大，重启更安全 |
| 默认开关 | 全部默认关闭 | 向后兼容；用户显式开启才生效 |

## 7. 安全与隐私基线

新增 `docs/security.md`，与 qq-bridge 的 `SECURITY_BASELINE.md` 对齐：

1. **控制台**：只绑 `127.0.0.1`；token 鉴权；token 文件权限收紧；密钥在 API 返回里一律打码；不做"远程访问"。
2. **注入面**：群消息/图片文字/搜索结果一律不可信；进入提示词前转义；不把群友文本当指令。
3. **工具面**：Phase 6 若引入工具，必须有白名单与"只读优先"。
4. **出站**：只连 `.env` 里配置的本机 OneBot 与模型 HTTPS 地址（现有校验保留）。
5. **落盘**：`data/`、`runtime/`、`logs/` 继续 gitignore；控制台 token 不入库。
6. **改动检查单**：动到鉴权/发送/预算的改动，必须先读 `docs/security.md` 并跑安全相关测试。
