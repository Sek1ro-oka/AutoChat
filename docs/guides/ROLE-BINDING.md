# 按互通组配置人格卡（T-035）

> 一句话：**人格卡不再全局唯一**。同一个互通组里的群聊与私聊共享一张卡，不同组可以用不同的卡，
> 没有分组的会话（编号 0）各自独立；默认人格仍然只有一份，供「继承默认人格」的组跟随。

## 1. 三种选项

| 选项 | 存进 config 的东西 | 默认人格变了会怎样 |
| --- | --- | --- |
| 继承默认人格 | **不存**（`bindings` 里没有这个作用域） | 跟着变 |
| 指定人格卡 | `{"mode":"card","name":"某张卡"}` | 不变 |
| 不使用人格卡 | `{"mode":"none"}` | 仍无人格（只有仿真预设） |

「没有配置」与「明确不用」是两件事，**不要用同一个值表达**。解析顺序：作用域绑定 → 全局默认 → 无人格；不拼接多张卡。

## 2. 作用域

- 编号 > 0 的会话：作用域 `cross:<gid>`，组内所有会话共用一份绑定。
- 编号 0（不共享）：作用域 `isolated:<会话key>`，**每条会话各自独立**，绝不聚合成「0 号组」。
- 解析是只读的：打开控制台或查提示词**不会**顺带替会话分配组号。

## 3. 存哪儿

```jsonc
// config.json
"role": {
  "maxInjectChars": 13000,
  "bindings": { "cross:1": { "mode": "card", "name": "小鲸鱼-嘴臭豆腐心" },
                "cross:2": { "mode": "none" } },
  "gids": [1, 2, 3]            // 已存在的组号（含没有成员的「闲置组」）
},
"socialV2": { "cross": { "groups": { "group:10001": 1, "private:20001": 1, "private:20004": 0 } } }
```

默认人格仍存在 `state/current-role.json`，**不复制进 config**。人格卡正文仍在 `roles/<名称>.md`。

- 新增互通组：编号 = 现有最大 + 1（升序、不补空号）。
- 闲置组（有绑定、没成员）：编号继续保留占用，「清除闲置绑定」后才允许指回，但新增编号仍按 max+1 走。
- 坏配置不会挡启动：非法绑定项被丢弃并记一条日志，`gids` 缺失时从 `groups` 反推。

## 4. 管理接口（只认 `x-console-token`，agent token 一律 403）

| 接口 | 用途 |
| --- | --- |
| `GET /api/roles/bindings` | 作用域列表（含 `members`/`idle`/`source`/`revision`/`missing`）、`nextGid`、`idleGids`、卡片摘要、当前 `revision` |
| `POST /api/roles/bindings/plan` | 只读预演：`impact.rebuild` / `rebindOnly` / `missing` / `conflicts` / `invalid` |
| `POST /api/roles/bindings/apply` | 一次提交 `groups + gids + bindings`（必须带 `baseRevision`）；旧版本 409、合并冲突 409、写盘失败 500，三种都**零修改** |

合并两个不同人格的组时，`apply` 带 `mergeChoice: { "cross:1": "最终卡名" | "none" }` 即可一步完成；
不带就返回 409 让用户先选。

## 5. 控制台在哪

「跨渠道互通」页（**不是**人格页）：

- **互通组总览**（吸顶、独立滚动）：编号 / 成员 / 生效人格（三态下拉）/ 内容版本 / 状态；底部「+ 新增互通组（编号 N）」「清除闲置绑定」。
- **会话与编号**：编号列是下拉（`0（不共享）` + 各组），改号进草稿。
- **底部操作条**：未保存变更 N 项 · 预览影响 · 保存 · 重置。保存是**一次** apply，不留「组变了人格没变」的中间态。
- 人格卡折叠区：查看 / 复制到组 / 编辑原卡 / 删除（被引用时先拦下并列引用清单）。

人格页只剩两件事：默认人格（只影响继承者）与人格卡库/编辑器。

## 6. 生效时机

- 保存后按 `impact.rebuild` 逐条退役受影响会话（撤销 token、停旧 DSH 会话），下一条消息进来时按需重建、注入新人格。
- 只在「作用域变了」或「生效内容摘要变了」时重建；只改绑法、生效文本没变的不重建。
- 已经发给 QQ 的消息追不回来；切换约束的是**尚未提交上游**的后续输出（`sessionPolicy` 里带了作用域与内容摘要，旧回合的发送/语音/图片会被拦）。
- 升级到本功能后第一次启动：旧的 3 元组会话策略在「继承默认」时**就地采纳**成新五元组，不退役、不丢上下文；
  显式绑卡 / 显式 `none` / 模式·preset·ownerQQ 真的变了的，才照常重建。

## 7. 排障

| 现象 | 看哪里 |
| --- | --- |
| 同组两个会话人格不同 | `GET /api/roles/bindings` 的 `scopes[].scope` 是否一致；提示词里 `role.scope` / `role.revision` 是否相同 |
| 改了组没生效 | `role.revision` 变了吗；`sessionPolicy` 变化后会退役，等下一次来信重建 |
| 保存报 409 | 另一个页面先改过：刷新再改；**不要**用旧 `baseRevision` 反复重试 |
| 卡缺失 | `scopes[].missing=true`：该会话暂停输出待修复，不会偷偷换成默认人格 |
| 提示词里没有【当前角色】 | 该作用域是 `none`，或绑定的卡文件已被删（`revision` 为 `missing:<名>`） |
