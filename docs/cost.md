# 令牌与花费看板

对应 [V2 开发路线图](roadmap.md) 的 Phase 5。这里说明**钱是怎么算出来的**，以及控制台「花费与令牌」页每一个数字的来源。

## 一句话口径

> 看板上的每一个 token 数都来自模型服务返回的 `usage`，落盘后由 SQL 聚合；控制台只是把聚合结果乘上你在 `.env` 里写的单价。**没有任何一个数字是本地估算出来的。**

估算值只出现在一个地方——**每日预算的预留**（见下文「与预算的关系」）。

## 峰谷分时

### 判定规则

来自 DeepSeek 官方计价文档原文：

> 北京时间周一至周五（不含中国法定节假日）9:00 - 12:00、14:00 - 18:00 为高峰时段；其余时段，包括周末及中国法定节假日全天均为空闲时段。

> 空闲时段价格为高峰时段价格的一半。

实现要点（`src/ledger.js` 的 `bucketAt`）：

| 情形 | 时段 |
| --- | --- |
| 周六、周日（含调休补班的周末） | 空闲 |
| 法定节假日全天 | 空闲 |
| 工作日 09:00–11:59、14:00–17:59 | 高峰 |
| 工作日 12:00–13:59 | 空闲 |
| 工作日 18:00–次日 08:59 | 空闲 |

边界取向：**右端点开区间**。12:00 整与 18:00 整已属空闲；09:00 整与 14:00 整属高峰。

### 节假日表

内置表在 `src/holidays.js`，当前覆盖 **2026 年**（依据国务院办公厅《关于2026年部分节假日安排的通知》，2025-11-04）：元旦 01-01～01-03、春节 02-15～02-23、清明 04-04～04-06、劳动节 05-01～05-05、端午 06-19～06-21、中秋 09-25～09-27、国庆 10-01～10-07。

- 表内没有的年份一律按「非节假日」处理。这会**高估**高峰时长、从而高估花费，属于保守方向。
- 每年国务院发布次年安排后需要追加对应年份。
- 临时补充（例如公司自定假日）走 `.env` 的 `COST_HOLIDAYS`，逗号分隔 `YYYY-MM-DD`。

## 单价

三个价格都按「人民币元 / 百万 token」计：

| 配置项 | 含义 | 缺省行为 |
| --- | --- | --- |
| `PRICE_INPUT_CNY_PER_MILLION` | 输入，**缓存未命中** | 必填（沿用既有配置） |
| `PRICE_OUTPUT_CNY_PER_MILLION` | 输出 | 必填（沿用既有配置） |
| `PRICE_CACHE_HIT_CNY_PER_MILLION` | 输入，**缓存命中** | 留空 = 未命中价的 **1/50** |
| `PRICE_OFFPEAK_RATIO` | 空闲时段相对高峰的倍率 | `0.5` |

1/50 的缺省值来自 DeepSeek 官方价目（`deepseek-flash`：缓存命中 0.04 / 未命中 2.00 高峰；0.02 / 1.00 空闲，正好 1/50）。**不上报缓存字段的服务商命中数恒为 0，这个缺省值不会被用到**；若你的服务商缓存折扣不是 1/50，请显式配置。

报表按**当前** `.env` 单价重算历史：改了价格，历史金额随之变化。这是刻意的——报表要回答「按今天这个价，这些用量是多少钱」。

## 数据从哪来

每一次模型调用（包括联网搜索的两次调用）成功后，`src/bot.js` 立刻把服务端的 `usage` 拆成三个互不重叠的桶写入 `token_samples`：

| 桶 | 来源字段 | 说明 |
| --- | --- | --- |
| 输入·未命中 | `prompt_cache_miss_tokens` | 服务商不上报时退化为 `prompt_tokens` 全额 |
| 输入·命中 | `prompt_cache_hit_tokens` | 不上报时为 0 |
| 输出 | `completion_tokens` | |

三个桶之和恒等于 `prompt_tokens + completion_tokens`，同一个 token 不会被记两次（有测试断言这条）。

### 三条不变量

1. **不自己累加总量**。进程内没有任何运行中的计数器；控制台的总量是 `SUM()` 聚合。这避免了「内存计数器与真实账单漂移」这类问题。
2. **幂等折叠**。主键是 `(session, turn, seq)` 拼出的 `turn_key`。同一次调用重放不会翻倍——`ON CONFLICT` 只在带**更新的时间戳**时才覆盖，否则是空操作（有测试断言重放返回 0 行变更）。
3. **先落盘再进内存**。采样一到就写 SQLite，没有 per-turn 缓冲，崩溃最多丢掉正在飞的那一次调用。

### 与路线图的一处修正

路线图写的是「按 `(session, turn, seq)` 建键」。直接实现会有一个隐患：**per-process 的 turn 计数在重启后从 1 重来**，`private:1:1` 会撞上上一次运行的同一键，把历史采样覆盖掉。

因此 turn 号改由 SQLite 的 `counters` 表分配（`newTurn()`，`INSERT ... RETURNING`），跨重启单调递增，`turn_key` 永不重复。测试 `the turn counter is monotonic across restarts so keys are never reused` 覆盖这条。

## 与预算的关系（重要）

| 用途 | 口径 |
| --- | --- |
| 每日预算预留 / 结算 | 高峰价 + 未命中价 + `MAX_OUTPUT_TOKENS`，**保守**（最贵情形） |
| 看板「区间花费」 | 真实分时价 + 真实缓存命中，**报表** |

两者**互不影响**：看板算出的「真实折算」永远不会让当日额度变宽松，也不会因为空闲时段打折就多放行一次调用。预留仍然是最坏情况估算。

## 控制台页面

「花费与令牌」页（`/api/cost`）包含：

- **四个指标**：区间花费（含高峰/空闲拆分）、累计 token（三个桶）、缓存命中率、平均每轮花费；
- **走势图**：24h / 3d 按小时、7d / 30d 按天；柱状堆叠，**高峰一色、空闲一色**，悬停显示该时段花费、token 与调用次数；
- **按会话表**：轮数、调用数、三个桶、命中率、花费、最后时间；**点击任意行下钻**到逐轮明细；
- **逐轮明细**：该会话每轮的时间、调用次数、三个桶、时段（高峰/空闲/混合）、花费；
- **最近采样**：最近 20 次调用的原始流水；
- **按账期**：预算账本本身的预留与结算（`charges` 表），与看板口径不同，故分开呈现。

时间桶按**北京时间对齐**：`7d`/`30d` 的一天从北京时间 0 点开始，与计费日一致（不是 UTC 0 点）。

## 数据上限

`token_samples` 保留最近 **20000** 行，超出部分在机器人的定期维护里按时间从旧到新裁剪（`pruneSamples`）。裁剪只删最旧的采样，不聚合、不改写其他行。

## 已知边界

1. **分段取整**：每一段（未命中/命中/输出）单独向上取整到微元，单条采样的误差上界为 3 微元（0.000003 元）。
2. **历史价格**：报表用当前单价重算历史，不保存「当时的单价」快照。
3. **节假日表需要人工维护**：表外年份按非节假日处理。
4. **失败调用不计入**：模型调用失败（`usage` 不可用）时不写采样，对应的 `charges` 行标记为 `uncertain`，在「按账期」里可见——这是账本层面的信息，不是看板的。
5. **采样不区分功能**：目前一条采样只记会话与轮次，不记「本次是搜索 / 图片 / 普通对话」。若日后要看分功能成本，需要给 `token_samples` 再加一列。

## 验证

```bash
npm test          # 含 test/ledger.test.js：峰谷边界、节假日、缓存拆分、幂等重放、跨重启单调、分桶聚合、裁剪
npm run check     # 用真实 .env 校验新增配置项
```

`test/ledger.test.js` 里的时间全部用北京时间构造：`bj(10, 8, 10, 0)` 表示 2026-10-08 10:00（周四，工作日，高峰）。
