# 按群特异化

三个子系统——人格、仿真、黑话——都能**按群**单独配置，而不是整个机器人一份。这是 V2 拟人化的延伸：同一个机器人，在 A 群可以是话痨少女，在 B 群可以是闷葫芦，各自的黑话与主动发言节奏也互不影响。

## 一句话口径

> **群覆盖 > 全局值 > `.env` 默认。** 没有覆盖的群，行为和升级前逐字节一致。

## 键与作用域

所有覆盖都是 `settings` 表里的**命名空间键**，沿用 `social_mute:<群号>` 的既有模式：

| 子系统 | 键 | 含义 |
| --- | --- | --- |
| 人格 | `group_persona:<群号>` | 该群用哪张人格卡；`''`=内置默认；缺失=继承全局 |
| 仿真 | `group_social_enabled:<群号>` 等 | 开关 / 阈值 / 冷却 / 日上限，各一条 |
| 黑话 | `group_slang_enabled:<群号>` | 该群黑话开关；缺失=继承全局 |

键名与数值边界统一定义在 `src/group-settings.js`（`GROUP_KEYS` / `GROUP_LIMITS`），因为**读方**（`personas.js`、`social/params.js`、`social/slang.js`）与**写方**（控制台群设置页）必须对同一套键达成一致——否则控制台会"存下一个没人读的值"，而且是静默的。

解析顺序（`src/social/params.js` 的 `resolveParams` 同理）：

```
.env 默认  <  全局 settings 键  <  按群 settings 键
```

一个群没有任何覆盖行时，解析结果就是全局值；因此没碰过「群设置」页的安装，行为与引入这一层之前完全一致。

## 三块各自怎么按群

- **人格**：`personas.active(group)` 先看 `group_persona:<群号>`，命中就用它，否则落到全局选择。`SYSTEM_PROMPT`（`.env`）一旦设置仍独占一切，按群覆盖也不参与。私聊没有群参数，始终用全局。
- **仿真**：`social.params(group)` 返回该群的**有效**数值（已合并覆盖），并附带 `overridden` 标记告诉控制台每一项是"该群自己的"还是"继承的"。静音 `social_mute:<群号>` 是更早的按群键，保持不变。
- **黑话**：
  - **开关**：`slang.params(group).enabled` 先看 `group_slang_enabled:<群号>`，否则全局。
  - **词条归属**：`slang_groups` 表（`slang_id, group_id`）。没有归属行的词条是**全局**的；有归属行的词条只注入列出的群。`slang.block({group})` 据此过滤。抽取时新词条自动关联到来源群，之后在「黑话」页单条详情里改「生效群」。

## 控制台

「群设置」页（见 [Web 控制台](console.md)）每个群一张卡：

- 人格卡下拉：`继承全局（当前值）` / `内置默认` / 各卡片名；
- 仿真：开关、阈值、冷却、日上限，未覆盖的项显示「继承」并可点「清除」回到继承；
- 黑话：开关 + 该群适用的词条数；
- 「恢复该群默认」清空该群全部覆盖（`clearGroupOverrides`）。

写入统一走 `POST /api/groups/config`，按 `subsystem` 分发给对应子系统；只接受已知群号（未知群 `404`）与已知子系统，数值由各子系统照旧做范围校验。

「群设置」页与人格／仿真／黑话页一样**不轮询**——它带着下拉与输入框，定时刷新会打断编辑。

## 安全

- 覆盖键由 `GROUP_KEYS` 生成，写入口**不接受任意键名**，群号须在 `config.groupIds`（即机器人实际服务的群）里。
- 数值经 `withinRange` 校验，边界与 `.env` 相同，按群值不可能超出全局值也允许的范围。
- 删除人格卡会自动把引用它的所有群覆盖清掉（`settingKeys` 前缀扫描），不会留下悬空选择。
- 删除词条、裁剪词库会同步清理 `slang_groups` 孤儿行。
