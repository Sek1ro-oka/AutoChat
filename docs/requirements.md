## 1. 产品目标

在 QQ 内提供接入 DeepSeek 等大语言模型的对话机器人：收到用户私聊后自动回复；在群内被用户 @ 时回复；支持连续对话和基本管理。首期服务一个群和一名私聊用户，在 Windows 本机运行；默认模型为 `deepseek-flash`，每日模型费用预算人民币 1 元。用户已暂时取消封号风险 5% 的约束。

## 2. 必须先确认的可行性条件

### 2.1 “QQ 账户 bot”的含义

| 路线 | 身份与使用方式 | 本项目的处理建议 |
| --- | --- | --- |
| QQ 官方机器人 | 创建平台机器人应用，通过官方授权接口收发消息；与普通个人 QQ 号的好友身份、入群流程可能不同 | 保留为替代路线；须确认申请资格、私聊及群聊权限 |
| 普通 QQ 号自动化 | 使用普通 QQ 账号，通过 NapCat 等非官方接入端及 OneBot 接口收发消息 | 按用户要求优先选择生态关注度较高的路线，暂定 NapCatQQ＋OneBot v11 |

**首选候选：普通 QQ 号＋NapCatQQ＋OneBot v11＋AutoChat 对话服务。** NapCat 是独立外部接入组件；AutoChat 调用其接口，不复制或修改 NapCat 源码。可参考 AstrBot／LangBot 的模型接入方式；最终采用现成框架还是轻量自建服务，在技术方案阶段比较每日预算与定时清理的支持情况。首期不要求安装完整大型框架。

抽样中 NapCatQQ 约 10.8k Stars，LuckyLilliaBot 约 3.6k，Lagrange.Core 约 3.0k；官方 botpy 约 919、botgo 约 389。由此推断普通账号接入在该样本中的开源关注度更高，**不能据此认定真实使用人数或全 GitHub 项目占比**。AstrBot／LangBot 支持多路线，不计入任一方用户总量。详细来源、比较口径和限制见 [GitHub 路线调研](./qq-route-research.md)。

腾讯公开文档提供 QQ 单聊和群聊发送接口，并说明被动回复、回复时效及频次限制。[腾讯官方消息发送文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)

平台接入说明包含主体与场景权限要求；公开文档和后台能力可能存在更新差异，实施前以实际后台权限及联调结果确认。[腾讯官方接入说明](https://github.com/tencent-connect/bot-docs/blob/main/docs/README.md)

### 2.2 风险评估（暂不设概率门槛）

- 用户已要求暂不考虑 5% 风险约束，本期不以概率证明作为开发或试运行门槛。
- NapCat 官方项目文档承认社交风控问题，GitHub 也存在账号异常报告；可以确认有风险，无法仅凭 Issues／Discussions 计算封号概率。
- 官方路线避免普通账号非官方登录这一类风险，但仍受应用权限、内容审核及平台处置影响；未查到两条路线具备分母、观察周期和统一定义的可信封号统计。
- 记录限制登录、限制发言、掉线和账号封禁，分别归类；不把掉线当成封号，也不把社区人数／Stars 当作风险样本分母。
- 建议使用专门的机器人账号；发现账号异常后暂停自动发送，交由管理员处理，不自动反复尝试登录。

## 3. 第一版功能范围

| 编号 | 需求 | 行为与边界 |
| --- | --- | --- |
| F01 | 私聊回复 | 向配置的私聊白名单用户开放文本对话，在同一私聊回复；每人上下文独立，用户白名单可修改。最新范围为原用户加九名新增用户 |
| F02 | 群聊 @ 回复 | 只响应明确 @ 本机器人的文本；@ 他人、普通群消息不触发；空内容 @ 返回简短使用提示 |
| F03 | DeepSeek 接入 | 默认 `deepseek-flash`；配置 API 密钥、模型名称、请求超时和输出上限，启动时验证配置 |
| F04 | 多模型扩展 | 接口地址、密钥和模型可配置；首期只实测 DeepSeek，不要求第二个服务，保留兼容接口扩展能力 |
| F05 | 连续对话 | 私聊按用户隔离，不设固定轮数或自动到期；按模型容量及预算裁剪最旧问答。群聊按“群＋用户”隔离，不读取整个群历史 |
| F06 | 会话清理 | `/清空` 清除当前会话；指定群所有机器人的对话上下文每 72 小时统一清空一次，新消息不顺延清理时间；私聊不受群清理影响 |
| F07 | 使用说明 | `/帮助` 展示触发方法、会话清理方式及消息会发往模型服务商的说明 |
| F08 | 管理控制 | 管理员私聊可启停回复、查看运行状态；用户／群白名单与默认模型在本机 .env 修改并重启生效，普通用户无管理权限 |
| F09 | 异常反馈 | 模型超时、额度不足或服务不可用时，尽可能在有效回复窗口内返回简短提示；不暴露密钥和内部异常 |
| F10 | 防重复 | 对重复事件去重；同一消息不重复调用模型；回复状态不确定时避免盲目重发 |

模型切换默认由管理员执行。更换模型服务商前应考虑对话数据的接收方变化；第一版不默认跨服务商自动重试。

## 4. 回复行为

1. 私聊示例：用户发送“帮我解释递归”，机器人使用当前会话上下文回答。
2. 群聊示例：指定群内用户发送“@机器人 帮我解释递归”，机器人在原群回答；识别结构化 @ 目标 QQ 号，不靠文本昵称判断。默认允许该群成员 @ 使用；私聊仍只开放指定的一人。
3. 群里用户只 @ 其他成员或未 @ 机器人时，不调用模型、不发送回复。
4. 默认使用简体中文，可以随用户请求切换语言；系统提示词由管理员配置。
5. 第一版优先发送完整文本，每次请求默认最多一条最终回复；超长答案先缩短，必要分段仍必须遵守平台限额。
6. 模型输出作为回复文本处理，不能修改管理员配置、访问其他用户会话或执行系统命令。

## 5. 风险控制与运行要求

下列措施是可验收的工程要求，不代表封号概率保证。

- 首选 NapCat 外部接入；本地 OneBot 接口与管理界面仅绑定回环地址并启用鉴权，避免其他人控制账号。
- 只处理用户主动发起的私聊与群 @；第一版不做主动推送、群发、自动加好友或自动加群。
- 初始限额：每用户每分钟 3 次请求、每群每分钟 10 次；首版全局串行处理，队列上限 20。最终限额必须取平台配额、模型配额与本地配置中的更严格值。
- 超限请求不进入模型队列；提醒也须限流，避免提示消息刷屏。
- 识别接口限频、权限撤销及持续发送失败；限频执行退避，权限或安全相关错误停止受影响发送并记录，管理员可手动恢复。
- 输入和输出都执行内容检查；检查规则、第三方审核服务是否启用及费用待确认，不能仅依赖模型系统提示词。
- 消息长度、接口配额等限制按最终接入端联调；若改用官方路线，再落实被动回复窗口及 URL 配置要求。
- 支持一键停用全部回复，以及单独关闭某个群。

## 6. 数据、隐私与费用

- API 密钥和 OneBot Token 放在环境变量或 `.env`，仓库仅提供无真实密钥的 `.env.example`；现有 `.gitignore` 已忽略 `.env`。账号会话文件与本地数据库也必须忽略。
- 使用本地 SQLite 保存当前对话上下文、群清理截止时间和每日费用账本；重启可恢复，避免重启绕过清理或预算。用户清空／群定时清理须删除对应上下文；第一版不实现额外的长期记忆或群历史采集。
- 群清理周期从首次启用起计 72 小时，截止时间持久化；停机错过清理时，在恢复后处理新请求之前清理到期群上下文。清理只针对 AutoChat 上下文，不删除 QQ 客户端或 NapCat 的历史消息。
- 日志默认记录时间、事件标识、耗时、错误码与用量；不记录完整聊天内容或密钥。标识脱敏，日志保留 7 天并轮转。
- 仅向用户选定的模型服务发送回答所必需的当前消息和该会话上下文；不发送整个群历史或其他用户会话。
- 每日模型预算为人民币 1 元，按 Asia/Hong_Kong 每日 00:00 切换账期；私聊与群聊、重试请求共用预算。重启不得重置已用费用。
- 发起请求前按完整输入、输出上限与最新配置价格预留最大预计费用，余额不足时拒绝模型调用；结束后用服务端 usage 核算。输入按未命中缓存价格保守预估；缺失 usage 或超时导致计费不确定时保留预留额。计价配置必须带币种与核验日期；不能以未经核实的固定问答次数代替金额预算。
- 长上下文会反复计入输入费用。私聊允许长期保留当前会话，但实际提交模型的上下文受模型容量和 1 元预算限制；必要时裁剪旧问答。费用控制不自动限制为 10 轮。
- `/状态` 可查看模型、当日已用／预留／剩余预算和下次群清理时间；预算耗尽时使用本地固定提示，不再调用模型。价格变动或其他程序共用 API Key 的消费不在本服务预算保证范围内。
- 用户删除当前会话后，不再用该上下文发起后续请求；已经发送至模型服务商的数据处理遵循相应服务政策。

## 7. 稳定性与部署

- 第一版：Windows 本机，一个机器人实例、一个指定群、一名指定私聊用户；无需公网服务器。本机关机、休眠或断网期间不保证回复。
- 模型请求超时默认 60 秒；首版不自动重试，避免超时后服务端已计费造成重复消费；用户再次提问需要另行预留预算。
- 同一会话顺序处理，避免连续提问造成上下文错位；队列长度有上限，过载时尽快返回提示。
- 支持受控重连和进程重启；不会因恢复连接把历史消息批量重发。
- 在平台和模型服务正常、测试负载不超限的条件下，建议 95% 文本请求在 60 秒内完成回复；具体负载需在验收前固定。
- 部署说明包含配置步骤、启动和停止、日志定位、白名单设置及密钥更换。框架和语言在接入路线确认后选择。

## 8. 第一版不包含

图片理解、语音、文件处理、联网搜索、自动执行工具、跨用户共享记忆、无需 @ 的群回复、营销群发及自建可视化管理后台。若采用现成框架，可使用其已有后台。后续可单独增加范围。

## 9. 验收条件

| 项目 | 验收方式 |
| --- | --- |
| 接入可行性 | 本机账号经接入端登录，并成功完成指定私聊及指定群 @ 收发 |
| 私聊与群 @ | 在平台与模型正常且不超限的条件下，各进行 20 次预定文本测试，均在正确会话完成回复 |
| 群触发边界 | 20 条无 @ 机器人消息及 10 条仅 @ 他人的消息，模型调用和机器人回复均为零 |
| 上下文隔离 | 真实私聊／群聊及模拟其他用户事件交叉验证，不串上下文；私聊不定时过期，重启后可恢复 |
| 定时清理 | 模拟时间跨越 72 小时及停机跨过截止时间，群上下文先清理后处理新消息；私聊保留，连续群消息不推迟清理 |
| 模型 | `deepseek-flash` 成功回答；模型与接口地址可配置；第二服务不列为本期验收项 |
| 异常处理 | 模拟超时、限频、无余额、权限失效与重复事件；无重复回复、无限重试或密钥泄露 |
| 管理与预算 | 普通用户不能执行管理操作；验证 1 元边界、输入和输出预留、重试、跨日、重启与 usage 缺失；不得发起预计超出剩余额度的请求 |
| 数据保护 | 仓库与默认日志不包含真实密钥或完整聊天内容；上下文清理生效 |
| 试运行 | 在指定的一人／一群中连续运行 7 天，记录停机、限频、发送失败与账号异常；不作为封号概率证明 |

## 10. 已确认参数与默认解释

后续范围更新优先于上文最初“一人一群”的规模说明：当前为十名私聊白名单用户和一个响应群，旧群停止响应；用户纠正的私聊号码已在本机配置中替换。预算仍为所有会话共用人民币 1 元／天。真正解散旧 QQ 群被自动审批阻止，需群主手动操作。

已确认：优先考虑社区采用较多的路线；暂不设 5% 风险门槛；一个群、一名私聊用户；本机部署；人民币 1 元／天；`deepseek-flash`；文本优先；私聊上下文长度可灵活处理；群聊约三天清理一次。

本稿默认解释：一个群内允许成员 @ 使用，私聊只对指定一人开放；群聊每 72 小时清理全部 AutoChat 群会话，群内不同成员的会话独立；私聊保留到手动清空、模型容量或预算要求裁剪。用户如有不同意图，可在确认时调整。

已进入开发阶段；本机账号标识与密钥只保存在 .env。开发文档、实现与测试持续更新；真实 QQ 链路需本人登录后验收。
