# AutoChat 开发方案与进度

日期：2026-10-02；路线：NapCatQQ 普通账号接入，用户已授权推进开发。

## 架构决定

采用轻量自建 Node.js 24 服务，NapCatQQ 作为独立外部组件。Node 内置 SQLite 保存会话、费用预留和事件去重；`ws` 提供带鉴权的 WebSocket 客户端。选择正向 WebSocket：NapCat 监听本机回环地址，AutoChat 主动连接，不需要公网服务器或事件回调端口。

消息流：NapCat OneBot 事件 → 身份与白名单过滤 → 结构化 @ 解析 → 持久化去重 → 有界串行队列 → 本地命令／限流 → 上下文容量处理 → 费用预留 → DeepSeek → usage 结算 → 文本消息数组发送。

首版全局串行处理、最多排队 20 条，满足一人一群的规模，也避免同一会话并发和群清理期间的竞态。后续有实际负载再增加并发；不先引入复杂锁机制。群消息不被 @ 时不写会话、不调用模型。模型答案以 text 消息段发送，避免模型生成 CQ 字符串被解释成图片、@ 或其他动作。

## 模块与约束

| 模块 | 职责 |
| --- | --- |
| config | 读取 .env 与环境变量；校验账号、回环地址、密钥和计价参数；日志不打印配置对象 |
| store | SQLite：会话、群清理时刻、事件去重、每日费用预留和结算、停用状态 |
| budget | 以人民币整数微元保存金额；香港时区账日；调用前原子预留；超时／usage 缺失保留额度 |
| model | DeepSeek 兼容 Chat Completions；超时、结构校验、输出限制；发送完整当前会话 |
| bot | 过滤触发、私聊／群成员隔离、命令、限流、上下文裁剪、内容规则、回复与异常处理 |
| onebot | 鉴权连接、echo 请求关联、发送结果确认、掉线退避、发送不盲目重试 |

私聊会话永久保留直到手动清空，模型输入受可配置上下文容量限制；按完整问答裁剪最旧内容。群内各用户独立会话，所有群会话每 72 小时清空，截止时间持久化。进程离线跨过截止时间，启动时先清理；在线时定期检查，清理与消息处理使用同一串行队列。

1 元预算使用每日账本。发送前按 UTF-8 字节数与消息封装余量估计输入 token 上界、按输出上限预留费用。该估计保守，但不是服务商 tokenizer 的形式证明；与 usage 对账发现不足预留时停止当日后续模型请求。非正常结束保留预留，防止超时后计费遗漏。首次上线必须人工核验实际人民币价格并配置核验日期；没有价格不允许启动付费模式。

模型请求不自动重试：已发出的超时请求可能收费，首次版本采用更保守策略；确需重试时由用户再次提问且另行预留。此项替代早期草案“临时失败重试一次”，避免双重计费及高延迟。真实流式发送暂不做，一次生成后发完整文本；答案按长度截断，不无限分段。

管理入口为指定私聊管理员；支持 /帮助、/状态、/清空、/停止、/启动、/群关闭、/群开启。白名单、模型、内容拦截词通过本机 .env 修改后重启生效，暂不实现聊天内修改密钥或服务商地址。管理员在停用期间仍可恢复。内容规则为可配置词列表，不宣称等同完整内容审核服务。

连接断开时中止待处理发送，保留不确定请求费用，暂停接收直到重连。去重跨重启保存；进程中断或发送结果未知的事件不自动重放。连续发送失败熔断，需要管理员 /启动 恢复；管理员操作受身份限制。

## 验证标准

自动化测试必须覆盖白名单、@ 他人、自己消息、会话隔离、群定时清理不延期、停机跨期、预算重启与跨日、并发预留、缺失 usage、模型异常、重复事件、管理权限、断线和文本安全发送。网络集成使用仅绑定 127.0.0.1 的假 OneBot 服务器和假模型服务器，不发送 QQ 消息、不消耗真实额度。

真实验收：指定用户私聊、群 @、普通群消息、/清空、/状态、预算截止、断开恢复。初次上线先验证本地命令，再开启模型调用。凭据由用户写入被忽略的 .env，数据库和 NapCat 下载／账号会话文件不进 Git。
