## 硬规矩

1. **文档与代码冲突时，以代码为准**，并回来改文档。
2. 复核命令是 `npm test`（全部测试）、`npm run check`（配置校验）与 `npm run check:docs`（文档链接与锚点）。文档里的数字、默认值、上限，都应当能在这三条命令或对应源码里复核到。
3. **新写的正文不写源码行号**——写「路径 + 符号名 + 最后核对日期」。行号会随每次改动漂移，写死了很快就会指到别的地方。这个规矩**只约束新写的文字**：`docs/security.md` 与 `docs/requirements.md` 里那批历史行号引用（登记为待清理项 **E-14**）已于 2026-10-17 清理完，换成符号名与章节名，两篇正文里不再有源码行号；以后再看到行号引用，照 E-14 的方式改成符号名，不要照抄。本文档表里的「最后核对」就是这篇文档上次逐句对过代码的日期。
4. **链接文本必须单行**，不要把一个链接拆到两行，否则渲染会断。
5. 本表只登记 `docs/` 内的文档；`docs/` 之外的文件（含只在本机存在、不属于仓库的工作区目录 `work`）一律不在这里登记。新增、改名或删除文档时，回来更新这张表。
